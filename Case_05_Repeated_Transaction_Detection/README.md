# Case Study 05: Repeated Transaction Detection

## Objectives
- Store transaction amounts in a list.
- Use nested loops to compare values and count matches.
- Use a second list to remember repeated amounts already found.
- Apply conditions to avoid printing a duplicate twice.

## Assumptions
- The entry count must be from 1 to 10.
- Transaction amounts must be positive integers.
- Equal amounts are treated as repeats for this classroom example; equal amounts alone do not prove fraud.
